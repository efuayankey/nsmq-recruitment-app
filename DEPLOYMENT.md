# Deployment

Two pieces: the Next.js frontend on Vercel, and the FastAPI backend + Postgres + Redis on Render.

## Backend + database (Render)

1. Push this repo to GitHub (the `render.yaml` at the repo root is a Render "Blueprint").
2. In the Render dashboard: **New > Blueprint**, point it at this repo/branch.
3. Render provisions three things from `render.yaml`:
   - `nsmq-backend` — the FastAPI app, built from `backend/Dockerfile`, running `alembic upgrade head` before every deploy
   - `nsmq-db` — managed Postgres
   - `nsmq-redis` — managed Key Value (Redis-compatible) store
   - `JWT_SECRET` is auto-generated by Render; `DATABASE_URL`/`REDIS_URL` are wired automatically between services
4. Once deployed, seed it once from the Render shell (Dashboard → nsmq-backend → Shell):
   ```bash
   python -m scripts.seed
   ```
5. Note the backend's public URL (e.g. `https://nsmq-backend.onrender.com`) — you'll need it for the frontend.

Plan names in `render.yaml` (`free`) are a starting point — check current plan availability/limits in the Render dashboard, they change over time.

## Frontend (Vercel)

1. Import this repo in Vercel, set the project **root directory** to `frontend`.
2. Set the environment variable `NEXT_PUBLIC_API_URL` to your deployed Render backend URL (from above).
3. Deploy.

## Wiring CORS after both are deployed

The backend only accepts browser requests from origins listed in `CORS_ORIGINS`. After your Vercel frontend has a real URL, update that env var on the Render backend service (Dashboard → nsmq-backend → Environment) to include it, e.g.:

```
CORS_ORIGINS=["https://your-app.vercel.app"]
```

Redeploy the backend after changing it — CORS origins are read at process startup, not hot-reloaded.
